## คนที่ 1: โมเดลคณิตศาสตร์และความน่าจะเป็น

### งานที่ต้องทำ

1. อธิบาย sensor model จาก `_get_evidence` เป็นสมการสำหรับข้อ 1.a
2. อธิบาย transition model ที่ใช้พารามิเตอร์อิสระตัวเดียวสำหรับข้อ 1.b
3. เขียน `_get_sensor_model` และ `_get_transition_model`
4. ตรวจความน่าจะเป็นของโมเดลด้วยตัวอย่างเล็ก ๆ และส่งต่อให้คนที่ 2
5. ช่วยวิเคราะห์ผลของพารามิเตอร์ผีต่อพฤติกรรมและ belief ในข้อ 3.d

### รายละเอียดสำคัญ

- Sensor ใช้ระยะ Manhattan บวก noise แบบ Binomial ที่เลื่อนค่าเฉลี่ยให้เป็นศูนย์ ไม่ใช่ Gaussian
- โค้ดกำหนด `p = 0.5` และ `n = int(sensor_variance / (p * (1 - p)))` ดังนั้นความแปรปรวนจริงเป็น `n * p * (1 - p)` ซึ่งอาจต่างจากค่าที่ป้อนเมื่อมีการปัดลง
- น้ำหนักการเคลื่อนที่ที่ระยะจาก Pacman ไม่ลดลง เทียบกับการเคลื่อนที่ที่ระยะลดลง คือ `1:1`, `2:1`, `8:1` สำหรับ `confused`, `afraid`, `scared` ตามลำดับ
- ต้อง normalize น้ำหนักเฉพาะทางเดินที่ใช้ได้จริง และพิจารณาตำแหน่ง Pacman ปัจจุบัน
- ในส่วนนี้ผีเดินย้อนกลับได้ และนโยบายผีตัดการหยุดนิ่งออกจากตัวเลือก
- คำตอบข้อ 1.a–1.b ต้องเป็นคณิตศาสตร์ ไม่อ้าง API และไม่ใส่ pseudocode

## คนที่ 2: Bayes filter และการรวมระบบ

### งานที่ต้องทำ

1. เขียน `_get_updated_belief` ให้เรียกใช้โมเดลของคนที่ 1
2. ทำขั้น prediction → correction → normalization
3. รองรับผีหลายตัว ตำแหน่ง Pacman ที่เปลี่ยนไป และผีที่ถูกกิน
4. ตรวจการทำงานร่วมกับเกม รวมถึงวิธีรันและ import ของโค้ดปัจจุบัน
5. รวมโค้ดของทีมและตรวจ PEP8/docstring
6. เขียนแนวคิดตัวควบคุมในข้อ 3.f และทำโบนัสใน `pacmanagent.py` เมื่อส่วนหลักพร้อมแล้ว

### เกณฑ์ตรวจรับ

- Belief ของผีที่ยังอยู่มีผลรวมเป็น 1 ไม่มีค่าติดลบ และไม่มีความน่าจะเป็นบนกำแพง
- ผีที่ถูกกินคืนเมทริกซ์ศูนย์ตามข้อกำหนด
- ทำงานได้กับผีหลายตัวที่ใช้นโยบายชนิดเดียวกัน
- ทำงานได้เมื่อ Pacman เคลื่อนที่ ไม่ใช่เฉพาะเมื่อยืนนิ่ง
- ตรวจกรณีผลรวมก่อน normalization เป็นศูนย์และกำหนดวิธีจัดการที่มีเหตุผล
- ไม่ใช้ตำแหน่งจริงของผีในการคำนวณ filter หรือตัวควบคุมโบนัส
- ตัวควบคุมข้อ 3.f ใช้เพียงตำแหน่ง Pacman, legal actions และ belief ปัจจุบันตามโจทย์

## คนที่ 3: การทดลอง กราฟ และรายงาน

### งานที่ต้องทำ

1. กำหนดตัวชี้วัดข้อ 3.a–3.b และเขียน `_record_metrics`
2. เตรียมสคริปต์รันทดลองซ้ำ บันทึกข้อมูล และวาดกราฟ
3. ทดลองครบ 2 แผนที่ × 3 ชนิดผี ที่ sensor variance ค่าเริ่มต้น
4. ทดลองเปลี่ยน sensor variance เพิ่มเติมสำหรับข้อ 3.e
5. สรุปค่าเฉลี่ยและ error bars พร้อมระบุความหมายของ error bars
6. ประกอบรายงานตามเทมเพลตโดยรับเนื้อหาจากคนที่ 1 และคนที่ 2

### ตัวชี้วัดที่แนะนำ

- **ความไม่แน่นอน:** entropy ของ belief โดยกำหนดให้พจน์ที่ความน่าจะเป็นเป็นศูนย์มีค่าเป็นศูนย์
- **คุณภาพ:** ระยะ Manhattan คาดหมายจากการกระจาย belief ไปยังตำแหน่งจริงของผี ค่าน้อยหมายถึง belief กระจุกใกล้ตำแหน่งจริงมากขึ้น
- ใช้ ground truth เฉพาะการประเมินผล ซึ่งโจทย์อนุญาต
- กำหนดให้ชัดว่าจะไม่นับผีที่ถูกกินอย่างไร เพื่อไม่ให้เมทริกซ์ศูนย์ทำให้สรุปผลผิด

### ชุดทดลองและการทำซ้ำ

| ปัจจัย | ค่าที่ใช้ |
|---|---|
| แผนที่ | `large_filter`, `large_filter_walls` |
| ชนิดผี | `confused`, `afraid`, `scared` |
| Sensor variance พื้นฐาน | `1.0` ตามค่าเริ่มต้นใน `run.py` |
| Sensor variance เพิ่มเติม | เลือกหลายระดับเพื่อเปรียบเทียบ โดยบันทึกค่าที่ใช้จริง |
| Seed | ใช้หลาย seed และบันทึกไว้ให้ทำซ้ำได้ |
| ระยะเวลาทดลอง | นานพอให้ตัวชี้วัดนิ่ง และใช้เกณฑ์เดียวกันระหว่างชุดเปรียบเทียบ |

จำนวนรอบและระยะเวลาต้องตัดสินจากการลู่เข้าของผล ไม่กำหนดตัวเลขตายตัวโดยไม่มีหลักฐาน ใช้นโยบาย Pacman เดียวกันในชุดที่ต้องการเปรียบเทียบ และบันทึกจำนวนผีด้วย

`run.py` ใช้ `--silentdisplay` สำหรับปิดภาพ และไม่อนุญาตให้ใช้ร่วมกับ human agent ค่าเริ่มต้น จึงต้องเลือกตัวควบคุมอัตโนมัติสำหรับการทดลองแบบไม่มีภาพ

## ลำดับส่งต่องาน

1. **ตกลง interface:** ทุกคนยืนยันรูปแบบข้อมูลและสูตรตัวชี้วัดร่วมกัน
2. **ทำงานพร้อมกัน:** คนที่ 1 ทำโมเดล คนที่ 2 เตรียมตัวกรองและการตรวจสอบ คนที่ 3 เตรียมเครื่องมือทดลองและกราฟ
3. **รวมและตรวจ:** ตรวจโมเดลและ filter กับกรณีเล็ก ๆ ก่อน รวมถึงผีหลายตัวและ Pacman เคลื่อนที่
4. **ทดลองจริง:** เมื่อ filter ผ่านการตรวจแล้ว คนที่ 3 รันชุดทดลอง คนที่ 1 ช่วยตีความ คนที่ 2 ทำ controller/โบนัสตามเวลาที่เหลือ
5. **จัดทำรายงาน:** ทุกคนส่งข้อความส่วนตัวเองให้คนที่ 3 รวมตามเทมเพลต
6. **ตรวจส่ง:** ทุกคนตรวจผล โค้ด ชื่อไฟล์ จำนวนหน้า และไฟล์ archive ร่วมกัน
