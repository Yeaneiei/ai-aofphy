# แผนแบ่งงานโปรเจกต์ 2 สำหรับ 3 คน

อัปเดต 4 ตุลาคม 2026 ตามที่ผู้ใช้ยืนยัน: อาจารย์ยกเลิกข้อ 3.c ทั้งข้อ
รวมกราฟ, error bars และข้อกำหนดจำนวนรอบ/ระยะเวลาทดลองเพื่อแสดงการลู่เข้า
ของตัวชี้วัด ไม่ต้องส่ง PDF และไม่ต้องเพิ่มชุดทดลองใหญ่เพื่อผ่านเกณฑ์ CI เดิม
ดูข้อกำหนดปัจจุบันใน [README.md](README.md)

## การแบ่งงาน

| ผู้รับผิดชอบ | ขอบเขต | สิ่งที่ส่งให้ทีม |
|---|---|---|
| คนที่ 1 | ข้อ 1.a–1.b; `_get_sensor_model`, `_get_transition_model`; ช่วยข้อ 3.d | สมการโมเดล โค้ดโมเดล และคำอธิบายพารามิเตอร์ผี |
| คนที่ 2 | ข้อ 2.a; `_get_updated_belief`; ข้อ 3.f และโบนัส 3.g | Filter ที่ถูกต้อง ผลตรวจ และแนวคิด/โค้ด controller |

ทุกคนเขียนคำอธิบายส่วนของตัวเองและช่วยตรวจโค้ดกับคำตอบ ไม่ต้องจัดทำกราฟ,
error bars หรือ PDF และไม่ต้องรันชุด 2 แผนที่ × 3 policies จนผ่านเกณฑ์ CI
เพื่อทำข้อ 3.c ที่ยกเลิกแล้ว คะแนนรวมใหม่ยังไม่ยืนยัน ไม่ปรับคะแนนข้ออื่นเอง

## โมเดลและข้อกำหนดที่ยังอยู่

- ข้อ 1.a–1.b ต้องเป็นคณิตศาสตร์ ไม่อ้าง API และไม่ใส่ pseudocode
- Sensor เป็นระยะ Manhattan บวก centered Binomial noise; `p = 0.5`
  และ `n = int(sensor_variance / (p * (1 - p)))` ความแปรปรวนจริงอาจถูกปัดลง
- น้ำหนักการเคลื่อนที่ที่ระยะจาก Pacman ไม่ลดลงเทียบกับที่ลดลงคือ
  1:1, 2:1, 8:1 สำหรับ confused, afraid, scared ตามลำดับ
- ผีเดินย้อนกลับได้ ตัด STOP จากตัวเลือกเมื่อมีทางเดิน และ normalize
  เฉพาะการเคลื่อนที่ที่ใช้ได้จริง โดยพิจารณาตำแหน่ง Pacman ปัจจุบัน
- ข้อ 2.a ใช้ prediction → correction → normalization และเรียกทั้งสองโมเดล
  รองรับหลายผีที่ใช้ policy เดียวกัน รวมถึง Pacman ที่เคลื่อนที่
- ข้อ 2.a ยังระบุให้ belief ลู่เข้าสู่บริเวณความไม่แน่นอนของผีแต่ละตัว
  ไม่ได้กำหนด 6,000 ตา หรือเกณฑ์ ±0.10 bits / ±0.25 ช่องของทีม
- ข้อ 3.d ยังต้องอธิบายผลพารามิเตอร์ผีต่อพฤติกรรมและ belief ในทั้งสองแผนที่
  โดยใช้โมเดลและตัวชี้วัด ที่ sensor variance ค่าเริ่มต้น
- ข้อ 3.e ยังต้องอธิบายผล sensor variance ต่อ belief
- ข้อ 3.f และโบนัส 3.g ใช้เพียงตำแหน่ง Pacman, legal actions และ belief

## ตัวชี้วัดและข้อมูลอ้างอิง

- ข้อ 3.a: entropy ของ belief หน่วย bits; พจน์ที่ความน่าจะเป็นศูนย์มีค่าเป็นศูนย์
- ข้อ 3.b: ระยะ Manhattan คาดหมายจาก belief ไปยังตำแหน่งผีจริง
- ใช้ ground truth เฉพาะประเมินผล ไม่ใช้คำนวณ filter หรือ controller
- ไม่นับผีที่ถูกกินใน metrics เพื่อไม่ให้เมทริกซ์ศูนย์ทำให้สรุปผิด
- ข้อมูล CSV/JSON, กราฟเดิมและสคริปต์ทดลอง/วิเคราะห์เก็บไว้อ้างอิง
  ไม่ใช่สิ่งที่ต้องส่ง ไม่ต้องเพิ่มจำนวนตาหรือ seeds เพื่อผ่านเกณฑ์ข้อ 3.c เดิม
- บันทึกเก่าใน `_archive/REVIEW.md`, `_archive/CONVERGENCE_PLAN.md` และ `_archive/STABILITY_RESULTS.md`
  เป็นประวัติการตรวจ ไม่ใช่รายการงานบังคับตามข้อกำหนดล่าสุด

## การตรวจโค้ดและ interface

| ข้อมูล | รูปแบบ |
|---|---|
| Sensor model | likelihood `[width, height]` |
| Transition model | `[new_x, new_y, old_x, old_y]` |
| Belief | รายการเมทริกซ์ `[width, height]` แยกตามผี |
| ผีที่ถูกกิน | เมทริกซ์ศูนย์ |
| พิกัด | `[0, 0]` คือมุมล่างซ้าย |

ตรวจว่า belief ของผีที่ยังอยู่รวมเป็น 1 ไม่ติดลบ และไม่มีมวลบนกำแพง
ตรวจหลายผี, Pacman เปลี่ยนตำแหน่ง, ผีถูกกิน และกรณี likelihood รวมเป็นศูนย์
เทียบโมเดลกับนโยบายผีและ posterior กับสมการบนกรณีเล็ก ตรวจ import,
PEP8 และ docstring ตามข้อกำหนด ตัวรัน `run.py` แบบไม่มีภาพใช้
`--silentdisplay` และต้องเลือก controller อัตโนมัติแทน human agent
