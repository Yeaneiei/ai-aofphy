# แผนแบ่งงานโปรเจกต์ 1 สำหรับ 2 คน

อ้างอิงข้อกำหนดจาก [README.md](README.md) และ [README หลัก](../README.md)
เอกสารนี้เป็นแผนการทำงาน ไม่ใช่รายการงานที่ทำเสร็จแล้ว

## เป้าหมายและสิ่งที่ต้องส่ง

สร้างเอเจนต์ Pacman ให้กินอาหาร หลบผี และทำคะแนนให้มากที่สุด โดยส่งไฟล์:

- `minimax.py` — อัลกอริทึม Minimax (45% ของคะแนน)
- `hminimax.py` — อัลกอริทึม H-Minimax (50% ของคะแนน)

ทั้งสองไฟล์ใช้คลาส `PacmanAgent` ตามแม่แบบ `pacmanagent.py` และเลือกการกระทำผ่าน `get_action` ส่วนรูปแบบโค้ด PEP-8 คิดเป็น 5% ของคะแนน README โปรเจกต์ 1 ไม่ได้กำหนดให้ส่งรายงาน

กลุ่มมีได้สูงสุด 2 คน และต้องใช้กลุ่มเดิมในโปรเจกต์ 1 และ 2 กำหนดส่งให้ยึดวันที่ตกลงกับอาจารย์

## การแบ่งความรับผิดชอบ

| ผู้รับผิดชอบ | งานหลัก | งานสนับสนุน |
| --- | --- | --- |
| คนที่ 1: __________ | พัฒนา `minimax.py` ให้ถูกต้อง | เตรียมชุดทดสอบ ทดสอบกรณีขอบ และช่วยตรวจผล H-Minimax |
| คนที่ 2: __________ | พัฒนา `hminimax.py` และฟังก์ชันประเมินสถานะ | วัดคะแนนกับจำนวนโหนด และปรับประสิทธิภาพ |

H-Minimax มักใช้เวลาปรับจูนมากกว่า จึงให้คนที่ 1 ช่วยงานทดสอบหลัง Minimax ใช้งานได้ ไม่จำเป็นต้องแบ่งจำนวนบรรทัดให้เท่ากัน

## ขั้นที่ 1: ทำความเข้าใจร่วมกันก่อนแยกงาน

- [ ] อ่าน README และแม่แบบ `pacmanagent.py`
- [ ] ทดลองรันเกมและอ่าน API ของสถานะเกม
- [ ] ตกลงการสลับตา: Pacman เป็นฝ่าย MAX และผีเป็นฝ่าย MIN
- [ ] ตกลงเงื่อนไขสิ้นสุดเมื่อชนะหรือแพ้ และวิธีใช้คะแนนเกม
- [ ] วิเคราะห์การเดินวนและสถานะซ้ำ เพื่อไม่ให้ค้นหาไม่สิ้นสุดหรือเลือกผลผิด
- [ ] ตกลงว่านับความลึก H-Minimax ต่อการเดินหนึ่งครั้งหรือต่อรอบ Pacman และผี แล้วใช้ให้สอดคล้องกัน
- [ ] ตกลงวิธีเลือกเมื่อหลายการกระทำมีค่าเท่ากัน เพื่อให้ทดสอบซ้ำได้
- [ ] กำหนดให้แต่ละคนแก้ไฟล์หลักของตนเอง และคุยกันก่อนแก้ไฟล์ร่วม

ข้อกำหนดที่ต้องรักษา:

- ดึงข้อมูลเกมผ่าน API ที่โจทย์อนุญาตเท่านั้น
- ใช้ `generatePacmanSuccessors()` และ `generateGhostSuccessors(agentIndex)` ในการขยายโหนดของแต่ละฝ่าย
- เอเจนต์ไม่รู้กลยุทธ์จริงของผี ห้ามออกแบบให้พึ่งข้อมูลว่ากำลังแข่งกับผีชนิดใด
- ส่งคืนการกระทำที่ถูกกฎหมายเสมอ
- ผีในโปรเจกต์นี้กลับหลังหันไม่ได้ เว้นแต่ไม่มีทางเลือกอื่น ให้ยึด successor ที่ API ให้มา
- แผนที่ที่มีแคปซูลไม่อยู่ในการประเมิน จึงไม่ต้องเพิ่มงานส่วนนี้เพื่อให้ครบข้อกำหนด

## ขั้นที่ 3: งานคนที่ 2 — H-Minimax และประสิทธิภาพ

### พัฒนา `hminimax.py`

- [ ] สร้างไฟล์จากแม่แบบ และใช้หลักการสลับฝ่ายที่ตกลงร่วมกัน
- [ ] เขียน Minimax แบบจำกัดความลึก โดยแยกสถานะจบเกมออกจากจุดตัดความลึก
- [ ] ออกแบบฟังก์ชันประเมินสถานะ เช่น คะแนนปัจจุบัน อาหารที่เหลือ ระยะถึงอาหาร และความเสี่ยงจากผี
- [ ] ตรวจว่าค่าประเมินส่งเสริมการกินอาหารและหลบผี ไม่ทำให้ยืนวนโดยไม่คืบหน้า
- [ ] ทดลองความลึกและน้ำหนักค่าประเมินหลายชุด แล้วเลือกจากผลการทดสอบ
- [ ] พิจารณาลดการค้นหา เช่น alpha-beta pruning โดยรักษาความถูกต้องของอัลกอริทึม
- [ ] เพิ่ม docstring อธิบายความหมายของค่าประเมินและรูปแบบการนับความลึก
- [ ] จัดรูปแบบตาม PEP-8

### วัดและปรับผล

- [ ] ทดสอบ `small_adv`, `medium_adv` และ `large_adv` ที่มีให้ กับผีทั้ง 3 แบบ
- [ ] บันทึกคะแนน ชนะ/แพ้ จำนวนโหนดที่ขยาย และเวลารัน
- [ ] เปรียบเทียบแต่ละรุ่นด้วยชุดแผนที่ ผี และ seed เดียวกัน
- [ ] ตรวจว่าปรับดีขึ้นกับผีชนิดหนึ่งแล้วไม่ทำให้ผีชนิดอื่นแย่ลงมาก
- [ ] ให้คนที่ 1 ช่วยทดสอบกรณีขอบและตรวจผลหลังปรับจูน

**เกณฑ์เสร็จ:** เล่นได้กับผีทุกแบบ ทำคะแนนสมเหตุสมผล และขยายโหนดในจำนวนสมเหตุสมผล เพราะเกณฑ์คะแนนพิจารณาทั้งสองอย่าง ไม่ใช่แค่ชนะเกม

## ขั้นที่ 4: ทดสอบร่วมและเตรียมส่ง

รันคำสั่งจากโฟลเดอร์ `project1` หลังสร้างไฟล์เอเจนต์แล้ว:

```console
python run.py --agent minimax --ghost dumby --layout small_adv --seed 42 --nographics
python run.py --agent hminimax --ghost dumby --layout small_adv --seed 42 --nographics
```

เปลี่ยน `--ghost`, `--layout` และ `--seed` ตามชุดทดสอบที่ตกลงกัน ใช้ตารางนี้บันทึกผล หรือเก็บเป็น CSV เพิ่มระหว่างทำงาน:

| รุ่นโค้ด | เอเจนต์ | แผนที่ | ผี | Seed | คะแนน | ชนะ/แพ้ | โหนดที่ขยาย | เวลารัน | ปัญหาที่พบ |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| | | | | | | | | | |

- [ ] ทั้งสองคนตรวจโค้ดข้ามกัน และอธิบายหลักการของทั้งสองอัลกอริทึมได้
- [ ] ตรวจการนำเข้าและการรันแต่ละเอเจนต์จากโฟลเดอร์ `project1`
- [ ] ตรวจว่าไฟล์ส่งไม่พึ่งสคริปต์ทดสอบหรือไฟล์ส่วนตัวที่ไม่ได้ส่ง
- [ ] ตรวจ PEP-8 ของ `minimax.py` และ `hminimax.py`
- [ ] ทดสอบซ้ำหลังแก้ไขครั้งสุดท้ายกับกรณีที่เกี่ยวข้อง
- [ ] ตรวจชื่อไฟล์ส่งให้ตรง และใส่ข้อมูลสมาชิกตามแบบส่งงาน
- [ ] ส่ง `minimax.py` และ `hminimax.py` ตามช่องทางที่อาจารย์กำหนด

การผ่านชุดทดสอบที่สร้างเองไม่ได้รับประกันคะแนนเต็ม เพราะโจทย์มีแผนที่ทดสอบส่วนตัวด้วย ให้ตรวจเหตุผลและความถูกต้องของอัลกอริทึมควบคู่กัน

## ลำดับทำงานที่แนะนำ

1. ทั้งสองคนอ่านโจทย์ ทดลองเกม และตกลงหลักการร่วมกัน
2. คนที่ 1 ทำ Minimax ขณะที่คนที่ 2 เตรียม H-Minimax และฟังก์ชันประเมิน
3. ตรวจผลบนแผนที่เล็กร่วมกัน เพื่อแก้ปัญหาพื้นฐานก่อนปรับประสิทธิภาพ
4. คนที่ 1 ขยายชุดทดสอบ ขณะที่คนที่ 2 ปรับ H-Minimax จากผลทดลอง
5. ตรวจข้ามกัน ทดสอบรอบสุดท้าย และเตรียมไฟล์ส่ง
