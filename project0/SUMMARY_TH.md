# สรุป Project 0: Pacman Search Agent

## 1. โจทย์ให้ทำอะไร

สร้างตัวแทน AI ให้ Pacman หาเส้นทางกินอาหารให้หมดและชนะเกม
โดยมีเป้าหมายให้ได้คะแนนสูงที่สุด ในเขาวงกตที่มีอาหาร แคปซูล และกำแพง แต่ไม่มีผี
ใช้โครงสร้างคลาส `PacmanAgent` ตามแม่แบบ `pacmanagent.py`
โดยเมธอด `get_action(state)` ส่งคืนการเดินครั้งถัดไป

ไฟล์ที่โจทย์ระบุให้ส่งมี **2 ไฟล์**:

| ไฟล์ | สิ่งที่ต้องทำ | สัดส่วนคะแนน |
| --- | --- | ---: |
| `bfs.py` | เขียน Breadth-First Search (BFS) ให้ถูกต้อง คะแนนและจำนวนโหนดใกล้เคียงตัวอ้างอิง | 20% |
| `astar.py` | เขียน A* ให้หาคำตอบที่ดีที่สุด และใช้ heuristic ช่วยลดจำนวนโหนดที่ค้นหา | 75% |
| รูปแบบโค้ด | เขียนตามมาตรฐาน PEP-8 | 5% |

ข้อกำหนดสำคัญ:

- อ่านข้อมูลเกมผ่าน API ที่โครงการกำหนดเท่านั้น
- ขยายสถานะเกมผ่าน `generatePacmanSuccessors()`
- ส่งคืนการเดินที่ถูกกฎหมาย
- ทดสอบเพิ่มเติมเอง เพราะผู้สอนจะใช้เขาวงกตใหม่ในการประเมิน

## 2. เราทำอะไรไปแล้ว

| ไฟล์ | งานที่ทำ | บทบาท |
| --- | --- | --- |
| `bfs.py` | สร้าง BFS ด้วยคิว FIFO ป้องกันสถานะซ้ำ และย้อนสร้างเส้นทางจากสถานะชนะ | ไฟล์ส่งหลัก |

| `test_search.py` | เพิ่มชุดทดสอบด้วยสถานะเกมจริง และเทียบคำตอบกับ Uniform-Cost Search (UCS) | ตรวจความถูกต้อง |

| `README.md` | เพิ่มคำอธิบาย วิธีเซ็ตอัพ วิธีรัน ผลทดสอบ และแก้ code fence ที่ปิดไม่ครบ | คู่มือใช้งาน |
| `SUMMARY_TH.md` | สรุปโจทย์ งานที่ทำ และวิธีใช้งานกับ environment เดิม | เอกสารฉบับนี้ |

## 3. แนวคิดของโค้ดที่เขียน

### สถานะที่ใช้ค้นหา

ทั้งสามอัลกอริทึมใช้ข้อมูลต่อไปนี้เป็นกุญแจระบุสถานะ:

```text
(ตำแหน่ง Pacman, ตำแหน่งอาหารที่เหลือ, ตำแหน่งแคปซูลที่เหลือ)
```

ตำแหน่งอย่างเดียวไม่พอ เพราะกลับมาที่จุดเดิมหลังจากกินอาหารแล้ว
ถือเป็นสถานะใหม่ที่ยังจำเป็นต่อการค้นหา
อาหารและแคปซูลเก็บในรูป `frozenset` เพื่อใช้เป็นกุญแจใน set/dictionary ได้

### BFS: หาทางชนะที่ใช้ก้าวน้อยที่สุด

ค้นหาทีละระดับ โดยนำสถานะเข้าคิวแล้วหยิบสถานะที่เข้าก่อนออกก่อน
จึงพบเส้นทางที่มีจำนวนก้าวน้อยที่สุดเมื่อแต่ละการเดินนับเป็นหนึ่งก้าว
บันทึกสถานะทันทีที่เข้าคิวเพื่อไม่เพิ่มสถานะเดิมซ้ำ

### A*: หาทางชนะที่ได้คะแนนสูงที่สุด

คะแนนเมื่อชนะใน Project 0 คิดได้เป็น:

```text
คะแนน = 10 × จำนวนอาหารที่กิน
       - 5 × จำนวนแคปซูลที่กิน
       - จำนวนก้าว
       + 500
```

ทุกเส้นทางที่ชนะกินอาหารครบเท่ากันและได้โบนัสชนะเท่ากัน
จึงเปลี่ยนเป้าหมายเป็นลดต้นทุนดังนี้ได้:

```text
g(n) = จำนวนก้าวที่เดินมา + 5 × จำนวนแคปซูลที่กินไป
f(n) = g(n) + h(n)
```

A* เลือกค้นหาสถานะที่มีค่า `f(n)` ต่ำก่อน โดยใช้ heuristic:

```text
h(n) = ระยะทางตามช่องเดินจาก Pacman ไปอาหารที่ใกล้ที่สุด
       + น้ำหนักต้นไม้เชื่อมอาหารที่เหลือทั้งหมดแบบต่ำสุด (MST)
```

MST เป็นค่าประมาณของระยะทางที่ต้องใช้เชื่อมอาหารทั้งหมด
เมื่อรวมกับระยะถึงอาหารแรกจะยังไม่เกินต้นทุนของเส้นทางที่ต้องเดินจริง
และยังไม่ได้บวกค่าแคปซูล จึงใช้เป็นค่าประมาณขั้นต่ำได้
โค้ดเก็บระยะทางและค่า MST ไว้ใช้ซ้ำ และเปิดค้นหาสถานะใหม่เมื่อพบต้นทุนที่ต่ำกว่า

**เหตุผลที่ BFS กับ A* ได้คะแนนไม่เท่ากัน:**
เส้นทางสั้นที่สุดอาจผ่านแคปซูลที่ทำให้เสียคะแนน
เช่น เดิน 4 ก้าวและกิน 1 แคปซูล มีต้นทุน 9
แต่เดินอ้อม 6 ก้าวโดยไม่กินแคปซูล มีต้นทุน 6 จึงได้คะแนนดีกว่า

### DFS: ตัวอย่างเสริม

ค้นหาลึกไปตามเส้นทางหนึ่งก่อนแล้วจึงย้อนมาทางอื่น
ใช้ชุดสถานะที่เคยขยายเพื่อป้องกันการวนซ้ำ
ไม่รับประกันเส้นทางที่สั้นที่สุดหรือคะแนนสูงที่สุด
โจทย์ระบุไฟล์ส่งหลักเป็น BFS และ A* ไม่ใช่ DFS

## 4. ผลที่ตรวจสอบแล้ว

ผลจากการรันก่อนจัดทำสรุปนี้ด้วย Python 3.12 แบบไม่เปิดหน้าต่าง:

| อัลกอริทึม | ด่าน | ผล | คะแนน | โหนดที่ขยาย | เวลาคำนวณ (วินาที) |
| --- | --- | --- | ---: | ---: | ---: |
| BFS | small | ชนะ | 497 | 23 | 0.002 |
| BFS | medium | ชนะ | 565 | 25,761 | 4.879 |
| BFS | large | ชนะ | 429 | 3,312 | 1.266 |
| A* | small | ชนะ | 500 | 11 | 0.002 |
| A* | medium | ชนะ | 568 | 282 | 0.069 |
| A* | large | ชนะ | 433 | 223 | 0.152 |

ทั้ง 6 ครั้งชนะเกม และ A* ได้คะแนนดีกว่าพร้อมขยายโหนดน้อยกว่าในทั้งสามด่าน
เวลาเป็นค่าจากการรันตัวอย่าง อาจเปลี่ยนตามเครื่องและ environment
ผลนี้ไม่ได้เป็นผลวัดจาก `tf-env` ของผู้ใช้

ชุดทดสอบอัตโนมัติผ่าน 5 กลุ่ม:

1. ทางอ้อมที่ไม่กินแคปซูลต้องได้คะแนนดีกว่าทางสั้นที่กินแคปซูล
2. ทางตัน ทางที่ต้องผ่านแคปซูล การย้อนผ่านตำแหน่งเดิม และอาหารที่เข้าไม่ถึง
3. เขาวงกตสุ่ม 20 แบบ เปรียบเทียบ BFS และ A* กับ UCS
4. สถานะที่ตำแหน่งเหมือนกันแต่อาหารหรือแคปซูลต่างกันต้องแยกออกจากกัน
5. การคืนคำสั่งเดินที่ถูกกฎหมาย และการหยุดเมื่ออยู่ในสถานะชนะ

ตรวจ PEP-8 ด้วย `pycodestyle` ผ่านสำหรับ `bfs.py`, `astar.py`,
`dfs.py` และ `test_search.py`
ยังไม่ได้ตรวจหน้าต่างกราฟิกจริงในการทดสอบดังกล่าว
และยังไม่มีผลประเมินจากด่านลับของผู้สอน

## 5. วิธีเรียกใช้กับ Miniconda เดิมของเรา

ผู้ใช้มี environment ชื่อ `tf-env` อยู่แล้ว จึงไม่ต้องสร้างใหม่ทุกงาน
environment เก็บ Python และไลบรารี ส่วนโฟลเดอร์โปรเจกต์เก็บไฟล์โค้ด
ทั้งสองอย่างอยู่คนละที่กันได้

เปิด Anaconda Prompt หรือ terminal แบบ Command Prompt ที่ใช้งาน Conda ได้:

```bat
conda activate tf-env
cd /d D:\GitHub\ai-aofphy\projects\project0
python -c "import numpy; print(numpy.__version__)"
```

ถ้าคำสั่งสุดท้ายแจ้ง `No module named 'numpy'` ให้ติดตั้งเพิ่ม:

```bat
conda install numpy
```

หาก terminal เป็น PowerShell ให้ใช้คำสั่งเปลี่ยนโฟลเดอร์นี้แทน `cd /d`:

```powershell
cd D:\GitHub\ai-aofphy\projects\project0
```

รัน A* หรือ BFS เพื่อเปิดหน้าต่างเกม:

```bat
python run.py --agentfile astar.py --layout medium
python run.py --agentfile bfs.py --layout small
```

รันแบบไม่เปิดหน้าต่างและทดสอบอัตโนมัติ:

```bat
python run.py --agentfile astar.py --layout large --silentdisplay
python -m unittest -v test_search
```

ชื่อด่านที่มีให้คือ `small`, `medium`, `large`
หากต้องการทดลอง DFS ให้เปลี่ยนเป็น `--agentfile dfs.py`

**ปัญหาที่เคยพบ:** รันจาก `D:\GitHub\ai-aofphy` แล้วขึ้นว่าไม่พบ `run.py`
สาเหตุคือไฟล์อยู่ใน `projects\project0` ต้องเปลี่ยนโฟลเดอร์ก่อน
ไม่ใช่ปัญหาที่ต้องสร้าง environment ใหม่
